# 青禾 People 产品需求文档

| 属性 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 对应产品 | 青禾 People 1.0.0 |
| 状态 | 交付基线 |
| 产品形态 | 响应式 Web 工作台，单人产品体验版 |
| 目标用户 | HRBP、招聘专员、人事运营、HR 负责人 |

## 1. 背景与目标

互联网企业的人才管理跨越招聘、入职、人事档案、组织编制和绩效多个环节。产品将常用流程集中到同一工作台，以可演示、可操作的业务闭环验证需求，并提供后续接入企业数据的边界。

本版目标：用户能够登录、查找员工、管理候选人并预览简历、推进录用和入职清单、处理待办以及更新绩效；桌面、平板和手机可以完成核心操作；交付可复现的源码与运行文件。

不以真实生产组织管理作为本版目标。薪资核算、社保税务、电子签署、招聘渠道同步、消息推送、复杂审批引擎、SSO、服务端权限、多租户与多人并发均不在本版范围。

## 2. 用户与场景

| 用户 | 主要场景 | 成功标准 |
| --- | --- | --- |
| HRBP | 查看团队人员结构、查询员工、追踪绩效 | 能从总览进入明细并保存有效更新 |
| 招聘专员 | 建立职位、登记候选人、查看简历、推进录用 | 候选人阶段推进后可生成待入职档案与清单 |
| 人事运营 | 更新档案、核对办理清单、处理事项 | 清单全部完成后才可办结，关联状态同步 |
| HR 负责人 | 查看编制、招聘、人力指标与操作记录 | 指标可结合明细解释，审计可检索与导出 |

以上为需求角色；当前版本仅一个体验账号，未实现角色隔离。

## 3. 信息架构

工作总览 → 待办与审批 → 员工管理 → 组织与编制 → 招聘管理 → 入转调离 → 绩效与成长 → 人力分析 → 系统与审计。全局搜索与侧边导航提供跨模块入口，小屏使用折叠菜单。

## 4. 功能需求与验收

优先级 P0 为核心闭环，P1 为辅助管理。下列需求均为本版范围。

| 编号 | 优先级 | 功能及规则 | 可验收结果 |
| --- | --- | --- | --- |
| AUTH-01 | P0 | 账号 admin、密码 123；错误提示；密码可显隐；会话 8 小时；支持退出 | 未登录无法进入工作台，错误凭据不建立会话；退出后回到登录 |
| HOME-01 | P1 | 总览展示人员、招聘、待办、日程及业务入口 | 入口跳转到对应模块；汇总随保存后的数据刷新 |
| EMP-01 | P0 | 员工搜索、部门/状态筛选、分页、详情、新增与编辑 | 必填、部门、邮箱格式和唯一性检查；更新后刷新仍保留 |
| EMP-02 | P1 | 员工列表导出 | 导出可下载，内容与筛选结果一致 |
| ORG-01 | P1 | 部门人员与预算编制展示 | 可查看组织现状及预算差异；预算不代表实际薪资成本 |
| REC-01 | P0 | 创建招聘职位，登记候选人，按阶段展示 | 候选人必须关联招聘中的职位，新增进入简历筛选 |
| REC-02 | P0 | 点击候选人预览简历，上传替换与下载 | 示例展示虚构履历；新候选人显示空态；文件格式/签名/大小不合法时拒绝 |
| REC-03 | P0 | 简历筛选→初试→复试→Offer→待入职，支持淘汰 | 仅顺序推进；待入职和淘汰为终态；录用只创建一次员工与入职清单 |
| LIFE-01 | P0 | 入职、转正、调动、离职事项及检查清单 | 缺少任何检查项不能办结；入职/转正办结员工为正式，离职办结为已离职 |
| LIFE-02 | P1 | 调动事项清单 | 清单记录办理进度；实际部门/岗位通过员工编辑维护，不自动调岗 |
| TASK-01 | P0 | 待办详情、通过与驳回 | 只有待处理事项可操作，已处理不可重复办理；不执行外部系统操作 |
| PERF-01 | P0 | 目标进度、评审状态与评分维护 | 进度/评分 0–100 整数；未评分保持空值；完成需进度 100 且有评分，完成后锁定 |
| ANA-01 | P1 | 人力分布、招聘及绩效分析 | 基于当前工作空间记录聚合，无对外数据请求 |
| AUD-01 | P1 | 操作记录检索、导出 | 成功写入形成记录；记录含动作、对象、摘要、时间 |
| NAV-01 | P0 | 导航、全局搜索、弹窗、提示与空态 | 键盘可执行搜索选择；弹窗操作后反馈结果；失败不误报保存成功 |
| DATA-01 | P0 | 浏览器工作空间与企业接口适配 | 默认不调用业务接口；存储不足保存失败且原数据不被部分改写 |

## 5. 核心流程

### 5.1 招聘到入职

新建职位 → 登记候选人 → 查看或上传简历 → 顺序推进面试与 Offer → 待入职 → 自动生成员工档案和入职清单 → 完成清单 → 办结 → 员工状态为正式。任一尚未终结的招聘阶段可淘汰；终态不可继续推进。重复点击受提交状态和业务状态约束。

### 5.2 员工维护

搜索/筛选 → 打开详情 → 编辑 → 校验 → 保存 → 列表及关联的生命周期、绩效姓名/部门同步。邮箱忽略大小写判重。失败时展示错误并保留此前已保存的数据。

### 5.3 绩效评审

进行中 → 更新进度 → 待评审 → 填写评分、进度达到 100 → 已完成。未完成记录可调整状态；完成记录不可修改。本版无评分校准、强制分布或审批链。

## 6. 数据模型

| 对象 | 关键字段 | 关系 |
| --- | --- | --- |
| Employee | id、姓名、部门、岗位、职级、状态、邮箱、入职日期 | 被生命周期与绩效通过 employeeId 引用 |
| Department | id、名称、编制预算、成本预算 | 员工与职位使用部门名称关联 |
| Job | id、职位名称、部门、数量、状态、负责人 | 候选人通过 jobId 引用 |
| Candidate | id、姓名、jobId、阶段、来源、简历 | 录用生成员工及入职清单 |
| Resume | 结构化履历，或 PDF/图片名称及内容 | 归属于候选人，单文件最大 2 MB |
| Lifecycle | employeeId、类型、生效日、负责人、状态、清单 | 办结时同步适用员工状态 |
| Task | 标题、类别、对象、优先级、截止日、状态 | 当前为独立待办，不驱动外部流程 |
| Performance | employeeId、目标、进度、评分、状态 | 评分可为空 |
| Audit / Event | 操作记录 / 日程 | 供检索与展示 |

字段类型以 src/types.ts 为准。样例业务日期固定为体验数据快照，操作审计时间采用当前时间；不应将样例指标解读为真实经营数据。

## 7. 非功能要求

- 适配：覆盖 360、390、768、1024、1440、1920 像素视口。页面不发生整体横向溢出；宽表格和招聘看板允许容器内滚动；手机弹窗可滚动且操作区可达。
- 交互：可见焦点、表单标签、按钮可操作、搜索键盘导航。文件预览失败时可通过打开/下载完成查看。
- 可靠性：数据写入整体提交，错误和容量不足可见；同一界面保存中避免重复提交。单人单窗口使用为支持边界；不提供跨标签页冲突合并。
- 性能：无远程字体或运行时第三方业务服务依赖；构建静态资源可缓存。文件转为数据 URL 会增加空间占用，总容量取决于浏览器。
- 隐私：分发文件不含开发者个人信息、机器路径、环境密钥、真实业务数据或开发研究资料；上传附件只保存在当前工作空间，默认不发送到服务器。
- 兼容：Node.js 24 构建，现代 Chrome、Edge、Safari、Firefox 浏览器作为目标。已实测范围与待验证范围见验收记录，不将配置覆盖等同于实测覆盖。
- 认证：体验登录不是安全边界，前端数据和固定密码可被访问者查看；生产接入必须替换为服务端认证授权。

## 8. 企业接入要求（后续范围）

通过 HrDataSource 契约替换数据源。生产服务负责会话、RBAC、字段校验、附件安全存储、审计留存、敏感字段保护、备份与恢复、幂等和并发控制。录用创建员工及清单应为事务。接口失败须返回规范错误，禁止把企业密钥放入前端构建环境变量。接入不视为本版已经实现。

## 9. 验收与交付标准

类型检查和构建通过；数据规则与接口适配测试通过；浏览器核心业务闭环通过；六种尺寸无页面整体溢出；运行脚本可在工程目录之外启动；静态服务不可读取源码或环境文件；交付扫描无禁止的个人与研究信息。多操作系统及容器检查由 CI 配置覆盖，只有实际执行成功才记录为通过。

交付物：完整源代码、依赖锁文件、预构建静态文件、启动脚本、Docker/Compose、CI、PRD、部署说明、接口契约、测试与验收记录、第三方许可、版本压缩包及校验和。

## 10. 后续迭代优先级

P0：企业认证与权限、事务 API、附件存储、数据备份；P1：多人协同、可配置审批、招聘渠道接入与通知；P2：绩效校准、人才盘点及更深入的经营分析。以上不构成本版交付承诺。
